# update/ —— 垛型宽度参数标定工具包

用现场照片 + YOLO 标注校准 [core/config/](../core/config/) 下 `pile_ID_*.json` 的
`width_ranges`（顶层箱"箱宽/垛宽"分档区间），使顶层剩余箱数判定准确且有足够余量。

## 数据格式（放 `data/` 下即可开始）

| 文件 | 说明 |
|---|---|
| `照片` | `{垛型}_{顶层真实剩余箱数}.jpg`，如 `3.10_5.jpg`、`4.7+2_3.jpg` |
| `同名 .txt` | YOLO 标注，每行 `class cx cy w h`，归一化到整幅图像 |

- **垛型写法** = 配置文件名里的 `x` 换成 `.`：`3x10→3.10`、`5x8→5.8`、`4x7+2→4.7+2`。
  新增垛型只要按此命名放照片，脚本自动从配置文件名推导映射，无需改代码。
- 每种垛型按剩余箱数从 1 到满层各拍一张（depletion 序列）；
  同状态二次拍摄加 `" (2)"` 后缀：`3.10_5 (2).jpg`（序号取括号前的数字）。
- txt 中 **class 1 大框 = 垛 ROI**（宽度归一化的分母），**class 0 及其他 = 烟箱**；
  顶层箱取画面最上方一行（按 cy 聚类自动提取），个别文件 class 号噪声（如 15/16）
  会自动退化为"最大框当 ROI"。

## 使用（仓库根目录执行）

```bash
python3 update/validate.py    # ① 校验：每张照片 判定箱数 vs 文件名箱数
python3 update/audit.py       # ② 余量审计：自身余量 + 翻转余量（默认阈值 0.015）
python3 update/audit.py 0.02  #    可自定义阈值
```

标准流程：

1. 照片 + txt 放入 `update/data/`
2. 跑 `validate.py`：`✗未命中` / `⚠假匹配` 的照片会列出**最近候选 pattern 和逐槽偏差**，
   据此修改对应 `pile_ID_*.json` 的 `width_ranges`（必要时参照相邻 pattern 补新 pattern）
3. 复跑 `validate.py` 直到全部 `✓`
4. 跑 `audit.py` 确认两项余量全部 ≥0.015：低于阈值的照提示把边界往簇间空隙中点挪
5. 提交配置改动，并同步到远程机 10.16.82.95 才会生效

## 判定口径（与生产代码一致）

- `norm_width = 箱像素宽 / 垛ROI像素宽`；顶层箱按中心 x **从左到右**逐槽比对
  `width_ranges[j]`（同时需 `visible_count` = 检出数、深度在 `depth_ranges` 内）。
- 匹配按**配置文件顺序，首个全部槽命中即返回**。两个推论：
  - 排在命中 pattern 之后的重叠 pattern 不构成威胁；
  - 新增 pattern 必须放在会被它误吸的旧 pattern **之前**。
- **自身余量**：实测宽度到命中区间边界的距离，太小 → 容易掉出区间失配。
- **翻转余量**：整张照片漂移成"错误箱数"所需的最小单槽漂移（只统计排在前面、
  箱数不同的 pattern）。`∞` = 前面没有可竞争的异箱数 pattern。
- 边界取值原则：放在相邻实测簇之间空隙的**中点**，保证双侧 ≥0.015。
- `depth_ranges` 本工具无法校准（照片数据不含深度），只动 `width_ranges`。

## 目录结构

```
update/
├── README.md          本文件
├── common.py          公共库：数据加载 / 垛型映射 / 生产同款匹配器
├── validate.py        ① 全量校验（退出码 0=全对）
├── audit.py           ② 余量审计（退出码 0=达标）
├── data/              照片 + 同名 txt（标定数据，注意体积勿误提交）
└── history/           2026-10-31 首次标定的一次性修改脚本与对照表
                       （断言旧值，重复执行会报错，仅作修改记录保留）
```
